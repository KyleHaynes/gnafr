13 September 2026

  • Say: twenty minutes, two live demos, and I want your worst addresses at the end.
  • Number / example: the G-NAF is ~15 million address records; the package matches against all of them from one file on disk.
  • Watch out: this is a walkthrough, not a pitch. Shout if you want an address tried live.

One line in, one data.table out

Messy free-text Australian addresses in. The best-matching G-NAF record, its coordinates, and a 0-100 score broken down by component out.

results <- gnaf_match(dt$address, con)
  • The whole character vector goes in one call: one row or a few hundred thousand
  • DuckDB holds the G-NAF on disk; the address table never enters R
  • Every row carries the G-NAF PID, the label, the coordinates and the score breakdown
  • Say: the interface is boring on purpose. A vector in, a data.table out, one row per match.
  • Number / example: 100k addresses in roughly 15-45 seconds on a laptop against QLD.
  • Watch out: never lapply() this per row. The speed comes from scoring inside DuckDB in bulk.
  • Transition: “The score is broken into components because there are two kinds of people in this room.”

Two audiences, one engine

High precision

“I need to know this exact dwelling.”

  • A wrong match is worse than no match
  • Unit-level correctness, record linkage, counts by address
  • Wants: high min_score, flat weight up, aliases resolved, a review queue

Normalisation

“I need a clean consistent string - and roughly the right spot.”

  • Coverage beats precision
  • Street or suburb level is fine
  • Wants: low min_score, street-only fallback on, address_label as the output

Same code path. Different arguments. I will tag slides as we go.

  • Say: this split is the thread for the whole talk; every knob makes sense once you know which side you are on.
  • Number / example: a wrong unit number is a real error for linkage; one house off is survivable for normalisation.
  • Watch out: you do not need two pipelines. One run can serve both, which is the closing slide.
  • Transition: “Both start from the same file, which you build once.”

Build the database once

library(gnafr)
con <- gnaf_connect("C:/temp/gnaf.duckdb")

gnaf_build_db(con, gnaf_dir = "C:/temp/G-NAF MAY 2026/Standard",
              states = c("QLD", "NSW"))   # or "all"
  • The free G-NAF Standard PSV product from Geoscape; it carries the official alias tables
  • One call runs gnaf_init(), gnaf_load_psv(), gnaf_build_street_aliases() and prints gnaf_status()
  • Result: a single DuckDB file. Copy it, share it, open it read-only from many sessions
  • Say: this is minutes of work, once per G-NAF release, not part of anyone’s daily run.
  • Number / example: after the build, alias rows are the majority of the table; locality synonyms alone are most of it.
  • Watch out: gnaf_load() takes the simpler G-NAF Core CSV but you lose the official aliases.
  • Transition: “Here is what sits around that file.”

The package, in two phases

Dotted line: candidate generation, scoring and ranking all run inside DuckDB.

  • Say: left box happens once, right box happens every run, and the only thing joining them is the file.
  • Number / example: gnaf_match() scores millions of candidate pairs in the database and only the top-ranked rows come back to R, wide.
  • Watch out: everything downstream (review app, threshold filter, geographies) works on that one data.table; nothing needs the database again except the geographies join.
  • Transition: “So what actually happens inside gnaf_match()?”

How a match is found

  • Most inputs stop at the postcode join: a cheap equi-join, then scoring
  • The expensive paths only run on the residue, so time scales with messiness, not row count
  • Say: it is a cascade. Each input drops out as soon as something is confident about it.
  • Number / example: “weak” means the best candidate scored at or below fallback_threshold, default 90; a coincidental right-number-wrong-street match lands in the low 80s, which is exactly what the fallback is for.
  • Watch out: the parser does the abbreviation work up front, so “Rd”, “ROAD” and “Rd.” all reach the join as ROAD.
  • Transition: “That leaves the question of what the score actually means.”

Reading the score

Component Weight
Street name 40
Postcode 20
Suburb 15
Street type 10
Number 10
Flat / level 5
Total Read it as
90-100 All components agree
75-89 Minor spelling variation
60-74 One real discrepancy
< 60 Dropped by default (min_score = 60)

95 = 20 + 15 + 40 + 10 + 10 + 0 - everything right, flat missing.

Precision: read the components, not just the total. Normalisation: min_score = 40 is a fine bar.

  • Say: the total is a sum of agreements, not a probability. Two 85s can mean very different things.
  • Number / example: postcode + suburb + number + type agreeing with the wrong street is 55 before any street-name credit; the street name is what carries the match.
  • Watch out: the bands are guidance. Calibrate on a labelled sample of your own data, and note that custom weights bypass the match cache.
  • Transition: “Easier to show than to explain.”

Live demo 1 - scores

# Full breakdown for one messy address
gnaf_match("unit 110 120 musgrave Road red hill 4000 QLD", con)[
  , .(address_label, total_score, score_postcode, score_suburb,
      score_street_name, score_street_type, score_number, score_flat)]

# Wrong street type: Avenue typed, Drive in G-NAF
gnaf_match("13 Fairway Avenue, Clear Island Waters QLD 4226", con,
           min_score = 0)[, .(address_label, total_score, score_street_type)]

# A number that does not exist on the street stays unmatched
gnaf_match("999 Musgrave Road, Red Hill QLD 4059", con, min_score = 0)
  • Say: run these three in order and read the component numbers aloud.
  • Number / example: the first one shows postcode fallback fixing 4000 to 4059 with the suburb; the second shows street type costing exactly its weight.
  • Watch out: the money shot is the third one: even at min_score = 0 a non-existent number is not forced onto a neighbour.
  • Transition: “Everything that just happened past the postcode join is fallbacks and aliases.”

Fallbacks and aliases

  • Locality fallback: best score <= 90 and the suburb disagrees, so the suburb name is fuzzy-matched to recover the right postcode and the input is re-scored
  • Deferred alias search: street and address aliases when the street name is weak; locality aliases when the locality is weak
  • Street-only fallback: street_only_fallback = TRUE matches number-free inputs to a street (needs gnaf_build_street_aliases())
alias_type Meaning
LOCALITY:SYN, LOCALITY:SR Suburb synonyms and street-in-suburb references (the bulk of alias rows)
STREET:SYN, STREET:ALT Street renamed or spelt differently
ADDRESS:SYN, ADDRESS:RA The same dwelling under another address or number range
street_only Built by gnafr for the street-level fallback 
gnaf_match(x, con, include_aliases = TRUE)              # default: aliases compete with core rows
gnaf_match(x, con, alias_types = c(NA, "LOCALITY:SYN"))  # core rows plus suburb synonyms only

Normalisation: turn street-only on. Precision: check alias_type on every match.

  • Say: aliases are real G-NAF rows that compete with the core rows; a match can legitimately land on one.
  • Number / example: locality synonyms are the majority of the loaded table, which is why they are only searched when the locality is weak.
  • Watch out: include_aliases = FALSE and an explicit alias_types are mutually exclusive; pick one.
  • Transition: “For the precision people, an alias hit is the start of the answer, not the answer.”

Resolving an alias to the real dwelling

gnaf_match("27 Ivo Street, Nundah QLD 4012", con,
           return_principal = TRUE, return_primary = TRUE)
#> address_label:          16 WALLY STREET, NUNDAH QLD 4012        (the property)
#> matched_address_label:  27 IVO STREET, NUNDAH QLD 4012          (the ADDRESS:SYN alias that scored)
  • return_principal swaps in the non-alias record; return_primary then swaps in the parent property
  • resolve_principal = TRUE instead adds principal_* columns and leaves the match untouched

Precision: this is how you count dwellings, not spellings.

  • Say: three real G-NAF rows for one unit: the alias, the principal, and the primary property it sits in.
  • Number / example: Ivo Street is a synonym for Unit 2, 16 Wally Street; the primary is 16 Wally Street itself.
  • Watch out: the score and rank still describe the row that matched, and the matched_* columns keep it; the cache stores the original candidate too, so the options can change between calls.
  • Transition: “Once you know which dwelling, you usually want to know where it sits.”

Saved geographies

# Compute a layer once from polygons and save it in the database
gnaf_add_geography(con, "sa2_2021", sa2_sf,
                   return_cols = c(sa2_code = "SA2_CODE21", sa2_name = "SA2_NAME21"))

# ...or register a table you already have
gnaf_register_geography(con, "sa2_2021", "gnaf_sa2_2021", points_crs = 7844)

# Then ask for it by name on every match
results <- gnaf_match(addresses, con, geographies = "sa2_2021")   # TRUE = every layer
  • Point-in-polygon runs once per database, not once per run
  • Columns are appended for the final returned PID, after principal/primary resolution
  • NA where no polygon contains the point; no nearest-polygon guessing

Normalisation: SA2 or LGA on every row, for free, forever.

  • Say: the expensive spatial join happens once against the G-NAF points and is stored beside them.
  • Number / example: gnaf_list_geographies(con) shows what is registered; spatial_lookup() still exists for ad hoc polygons.
  • Watch out: a geography column that collides with an existing results column is an error, not a silent overwrite.
  • Transition: “Now the part everyone actually spends their time on: looking at the results.”

Reviewing results

gnaf_app(con)

  • Paste addresses, run the same gnaf_match()
  • Input-vs-matched diff on every row
  • Jaro-Winkler, Jaccard and Levenshtein text scores alongside the component scores

gnaf_threshold_filter(results)

  • A range slider on every score, text scores included
  • In-scope and out-of-scope tables move live
  • Flag individual inputs as false positives
  • Done prints the filter as code
gnaf_threshold_filter(results)
#> ## data.table
#> results[matched == TRUE & total_score >= 80 & score_street_name >= 30 & !input_id %in% c(41)]
#> ## dplyr
#> results |> dplyr::filter(matched == TRUE, total_score >= 80, score_street_name >= 30, ...)

Precision: find the false positives. Normalisation: find the bar.

  • Say: the threshold argument stops being an opinion in a meeting and becomes a line of code in the repo.
  • Number / example: flagging a row excludes its whole input_id, every rank, because that is what a false positive means.
  • Watch out: thresholds on the text scores wrap the result in gnaf_text_scores() in the printed code, so the snippet runs as-is on a plain gnaf_match() result.
  • Transition: “Let me do it rather than describe it.”

Two recipes, one file

High precision

gnaf_match(x, con,
  max_results = 3,
  min_score = 90,
  weights = list(postcode = 15, suburb = 10,
                 street_name = 35, street_type = 5,
                 number = 25, flat = 10),
  return_principal = TRUE)

Normalisation

gnaf_match(x, con,
  max_results = 1,
  min_score = 40,
  street_only_fallback = TRUE,
  include_aliases = TRUE)[
  , .(input_raw, address_label,
      longitude, latitude)]

Or match once at min_score = 0, keep every column, and let each consumer filter with the line the threshold app printed.

  • Say: same engine, same database file, two argument sets.
  • Number / example: the precision recipe moves 15 points of weight from street name onto number and flat because that is where a wrong dwelling shows up.
  • Watch out: custom weights mean no match cache; if the weights are stable, tell me and I will key the cache on them.
  • Transition: “Filtering is free, re-matching is not. Match once. Here is how to get it.”
